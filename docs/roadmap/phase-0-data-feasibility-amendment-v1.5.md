# 阶段 0 数据可行性修订 1.5

> 当前状态：`ACHIEVED / GO`。本修订以最终多源快照和离线重放证据取代 1.4 在旧数据源策略下的 `HOLD` 结论。

## 这次要解决什么

阶段 0 的目标用一句话说：证明我们现在能拿到双色球和大乐透各 200 期连续、完整、可追溯且能互相核对的历史开奖数据，后续研究不用建立在空数据或脏数据上。

阶段 0 不训练预测模型，也不评价哪种模型更准。历史开奖数据就绪只允许进入下一阶段研究，不意味着开奖号码具有可预测规律，更不支持“无限逼近 100%”的结论。

## 数据源调整

官方国家站在当前环境中的可访问性不稳定，所以不再把“国家官方接口持续可用”作为阶段 0 的唯一通路。修订后的实际采集使用两个不同运营主体的普通公开历史页面：

- 一定牛：较新的专业彩票历史档案，作为冻结窗口的主档案；
- 东方财富彩票频道：大型门户历史档案，作为逐期交叉发布核对来源。
- 广东体彩：只在门户档案确定缺期时读取对应的普通静态官方公告页；本次用于核对东方财富缺少的大乐透 2026026、2026027 两期。

500 的批量接口和 17500 的 API 被各自 robots 明确禁止，本方案不使用。要求授权后才能复用的官方省级批量页也不进入自动采集。本次快照只用于项目内部数据可行性研究；上线采集服务或分发数据前必须重新审查条款。

两个网站都转载同一个官方开奖事实。因此这里的“两源一致”只能发现网页更新、字段抽取和历史档案错误，不能声称存在两个独立摇奖真值。

## 怎么避免挑数据

每种彩票先找主档案和至少一个核对来源都已经发布的最新一期，以它作为固定锚点。然后严格按照主档案的开奖顺序向前取 200 期，再检查每一期是否至少得到另一个运营主体完全相同的期号、日期和号码。门户分页本身缺期时，允许按确定性规则读取对应的普通官方公告页补充核对，但不允许跳过该期后再补一个一致期。

门户更新比主档案慢的最新几期会被单独报告为“发布滞后”，不会混入冻结窗口，也不会伪装成冲突。

## 可信交付物

一次阶段 0 快照包括：

- 每个请求的开始、成功或失败事件；
- 原始页面、来源 URL、抓取时间、字节数和 SHA-256；
- 每个来源的标准化记录；
- 逐期对账结果和最终 400 条共识记录；
- 两种彩票各自的连续性、缺失和冲突报告；
- 离线重放结果。

验收以 [1.5 机器合同](./phase-0-acceptance-contract-v1.5.json) 为准。两个彩种都必须达到 200/200、一条不缺、一个冲突没有，并通过离线重放，阶段 0 才能标记为 `ACHIEVED / GO`。

最终机器报告位于 `artifacts/phase-0-multisource/snapshots/20260802T025000Z/phase0-report.json`，离线重放结果位于同目录的 `offline-verification.json`。
