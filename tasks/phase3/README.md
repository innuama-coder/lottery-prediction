# 阶段 3：模型研究基线定义

版本：1.0
状态：阶段定义
更新时间：2026-08-07

## 1. 文档定位

本文档定义阶段 3 的整体目标、工作内容、边界、约束、交付物、验收标准和验收方法。本文档不拆分阶段 3 的实施任务，不定义开发排期，也不表示阶段 3 已经实施或验收。

阶段 3 继承已验收的 Phase 1 数据基线和 Phase 2.1 统计边界。Phase 2.1 的最终交付状态为 `GO`，科学分类为 `indeterminate`；后者表示当前注册检验和功效不能形成更强结论，不表示证明彩票随机，也不阻止阶段 3 建立受约束的模型研究基线。

## 2. 阶段目标

阶段 3 的目标是：

> 建立并实际运行一个无未来信息泄漏、可重复、可独立复算的历史模型研究基线，比较均匀模型 M0 与低复杂度 challenger，判断是否有模型具备进入后续前瞻 shadow 验证的资格。

阶段 3 必须回答以下问题：

1. 候选模型能否对合法彩票组合输出非负、归一化的联合概率。
2. 候选模型在严格的时间滚动评估中是否比均匀模型 M0 表现更好。
3. 观察到的改善是否跨时间折稳定、可以复算，并且不是未来信息泄漏、选择性报告或反复搜索造成的。
4. 哪些模型应当淘汰、归档、保持未开放，或取得进入后续前瞻 shadow 验证的资格。

阶段 3 的成功不要求发现优于 M0 的模型。没有任何 challenger 合格，只要研究过程、证据和验收闭包完整，仍然是有效且可通过验收的阶段结果。

## 3. 工作内容

阶段 3 的整体工作包括：

- 冻结 Phase 1 数据身份、Phase 2.1 验收身份、统计功效边界、规则版本、彩种范围和允许使用的字段。
- 在生成正式模型比较结果之前，冻结时间折、主指标、辅助指标、守护指标、模型与特征搜索范围、错误预算、资源预算和停止规则。
- 建立模型注册表和特征注册表，记录数学定义、输入来源、预测时点可得性、泄漏风险、适用规则段、消融组、开放条件和终态。
- 建立统一的历史模型研究工具，使所有候选模型使用相同的输入、时间折、评估器、证据格式和失败处理规则。
- 完整实现并验证 M0 均匀固定基数无放回模型和 M1 静态贝叶斯加权子集模型。
- 登记 M2 至 M4 的数学规格、开放条件和淘汰条件；开放条件不满足时允许保持 `not_opened`，不要求为了形式完整而强制实现。
- 分别对双色球和大乐透执行 expanding-window rolling-origin 历史评估；每个外层目标期只能用于一次最终评价。
- 保存全部成功、失败、超时、崩溃和被淘汰的正式实验，不只保留表现最好的运行。
- 对逐期联合概率、联合 log score、边际 Brier、校准、负控、敏感性和稳定性进行统一计算与报告。
- 验证 Top-1000 生成接口、组合合法性、概率覆盖质量和可重复性，但不把 Top-1000 命中作为主要模型选择指标。
- 使用独立复核路径重算数据折分、模型概率、核心指标和最终模型分类。
- 形成阶段 3 最终研究报告、证据清单和唯一验收结论。

## 4. 工作边界

### 4.1 阶段内工作

- 历史模型研究和历史时间滚动评估。
- 历史 sequence-safe 特征快照、标签解锁和外部 point-in-time 泄漏验证。
- 模型、特征、指标、时间折和实验注册。
- M0、M1 研究实现及符合开放条件的低复杂度 challenger 研究。
- 联合概率、校准、负控、敏感性和稳定性评估。
- Top-1000 研究接口及概率覆盖验证。
- 实验账本、失败记录、独立复算和最终验收。

### 4.2 阶段外工作

- 不累积真实未来开奖的长期 shadow 证据。
- 不把任何 challenger 晋升为正式 Champion。
- 不建设生产预测服务、WebUI、在线 API、调度平台或数据库服务。
- 不执行自动购彩、代购、投注、收益测算或资金操作。
- 不作中奖保证、收益保证或“预测概率接近 100%”等主张。
- 不根据历史回测直接对外发布非均匀预测结论。
- 不默认开放 LSTM、Transformer、强化学习等高容量模型。
- 不使用当期销售额、奖池、中奖注数、媒体解释等开奖后字段预测当期开奖号码。
- 不把号码形态替代为不存在的摇奖机、球组、物理摇出顺序或维护记录。

## 5. 核心约束

1. **M0 永久保留。** 均匀固定基数无放回模型 M0 是阶段 3 的默认 Champion；历史结果不能自动替换它。
2. **历史证据不授予晋级。** 历史回测最多产生 `shadow_candidate`，不能触发 Champion 晋级或生产发布。
3. **逐彩种研究。** 双色球和大乐透分别训练、评估和分类，不合并样本、指标或统计证据来提高功效。
4. **预测时点约束。** Phase 1 历史开奖号采用 `retrospective_sequence_safe` 合同：作为特征的来源期必须严格早于目标期，所有变换只能在目标期以前的训练前缀上拟合，并且预测制品必须在评分器读取目标标签前不可变落盘。只有外部时变特征才要求真实 `available_at_utc < prediction_locked_at`；无法建立该时间证据的外部字段不得进入模型。
5. **外层评价隔离。** 训练、归一化、分箱、特征选择、超参数选择和模型权重学习只能读取外层目标期以前的数据。
6. **联合概率合法。** 模型只能向合法固定基数组合分配非负概率，且完整组合空间上的概率总和必须为 1。
7. **主指标固定。** 主要模型比较指标是相对 M0 的逐期联合 log-score skill；Brier、校准、稳定性和负控是辅助或守护指标。
8. **Top-1000 不作主门。** Top-1000 只用于输出接口和长期观察，不能替代严格适当的概率评分。
9. **结果前冻结。** 模型、特征、时间折、指标、阈值、搜索范围和决策规则必须在正式结果生成前冻结。
10. **实验变更可归因。** 每次正式实验原则上只改变一个模型、特征族或训练因素；组合变更必须在实验注册中说明理由。
11. **不选择性报告。** 所有注册实验必须有终态；失败、超时、方向相反和不显著结果不得删除。
12. **历史异常无特权。** Phase 2 的历史异常只能形成普通 challenger 假设，不能绕过模型、特征、错误预算或评估门。
13. **复核角色分离。** 独立复核人不得同时编写被复核实现或批准其模型分类；流程独立即可，不要求外部机构审计。
14. **执行环境不设通用门槛。** 不以架构、CPU、内存或磁盘快照值判断阶段成败；只记录实际环境、资源预算和是否完成批准工作负载。
15. **实用信任边界。** 阶段 3 信任受控执行者和仓库历史，不要求对抗恶意操作者的密码学执行证明；普通哈希和不可变记录用于复算与完整性核对。

## 6. 模型范围

- **M0 均匀无放回模型：** 必须完整实现并永久保留为默认 Champion。
- **M1 静态贝叶斯加权子集模型：** 必须完整实现，是阶段 3 的第一 challenger；其参数为零时必须严格退化为 M0。
- **M2 动态状态空间加权模型：** 必须登记规格和开放条件；没有足够证据时保持 `not_opened`。
- **M3 固定基数二阶交互模型：** 只允许少量预注册交互；禁止无约束搜索全部号码对。
- **M4 GBDT 或正则逻辑回归边际模型：** 仅作为诊断 challenger，必须经过固定基数联合概率投影后才能进入统一评分。
- **M5 热冷号、遗漏和 Markov 启发式：** 只能作为负控或复现实验，不能晋级。
- **M6 LSTM、Transformer 和强化学习：** 阶段 3 默认禁止。
- **M7 文献专用模型：** 只有在相同输入、时间折和评估器下完成复现后才能评审，不因论文中的历史结果直接开放。

## 7. 阶段交付物

阶段 3 最终交付一个完整、可独立验收的“模型研究基线包”。该交付包必须包含：

- 阶段 3 总体设计和机器可读验收合同。
- 输入 manifest、预注册和 Phase 1/Phase 2.1 身份引用。
- 历史序列关系 ledger、标签解锁 ledger，以及外部时变特征（如有）的 availability ledger。
- 模型注册表。
- 特征注册表和泄漏风险清单。
- M0/M1 数学规格、研究实现和统一评估工具。
- Phase 3 CLI、结果 Schema、测试和依赖锁。
- 完整实验注册表及失败实验账本。
- 分彩种的时间滚动预测、逐折指标和汇总结果。
- 联合 log score、Brier、校准、负控、敏感性和稳定性结果。
- Top-1000 接口、概率覆盖和可重复性记录。
- 模型分类结果和分类依据。
- 独立 replay 及复核报告。
- 最终证据 manifest 和阶段 3 acceptance 制品。

模型科学分类至少允许：

- `rejected`：模型违反概率、隔离、ledger 或其他完整性约束；单纯历史表现不足不得归入此类。
- `archived`：过程完整但未通过 shadow 门，且不满足预注册的 `indeterminate` 区间条件。
- `shadow_candidate`：满足历史研究门，可以进入后续前瞻 shadow 验证。
- `not_opened`：复杂模型的开放条件尚未满足。
- `indeterminate`：过程完整、非 bootstrap/Holm 门全部通过，并且至少一个彩种的冻结 bootstrap 区间跨越实质正向边界。

模型科学分类与阶段交付状态必须分开。阶段 3 可以在没有任何 `shadow_candidate` 的情况下获得 `PASS / GO`。

## 8. 验收标准

阶段 3 只有在以下条件全部满足时才能得到 `PASS / GO`：

1. Phase 1、Phase 2.1 和阶段 3 输入身份完整且相互一致。
2. 彩种范围、规则段、训练窗口、历史序列关系、外部特征可用时间和预注册均已冻结。
3. 所有历史来源期严格早于对应目标期；预测先于目标标签解锁。所有外部时变字段（如有）通过 point-in-time 和泄漏检查。
4. M0 与理论均匀概率一致并可确定性复算。
5. M1 只生成合法组合，概率归一，且零参数时严格退化为 M0。
6. 所有实际运行模型通过组合合法性、概率非负、概率归一和固定种子复算检查。
7. expanding-window rolling-origin、内部调参和外层评价之间没有数据交叉污染。
8. 每个外层目标期只进入一次最终评价，没有结果后重切时间折。
9. 主指标、辅助指标、守护指标、逐折结果、负控和敏感性结果完整。
10. 双色球和大乐透分别报告，没有跨彩种合并证据。
11. 所有注册实验都有终态，失败和不利结果没有被删除或覆盖。
12. 历史结果只产生 `rejected`、`archived`、`shadow_candidate`、`not_opened` 或 `indeterminate`，没有直接改变 Champion。
13. 独立 replay 在冻结容差内复算核心输入、折分、概率、指标和模型分类。
14. 必需正向与负向 E2E 全部达到预期终态。
15. 交付物覆盖率和证据血缘完整，阻断问题为 0。
16. 最终报告没有把历史表现表述成真实前瞻优势、随机性证明、中奖保证或收益保证。

阶段交付状态与科学结果的关系如下：

| 阶段交付状态 | 科学结果 | 含义 |
| --- | --- | --- |
| `GO` | 存在 `shadow_candidate` | 有模型可以进入后续前瞻 shadow，但尚未胜过 M0 |
| `GO` | `no_shadow_candidate` | 没有模型合格，M0 继续保持默认 Champion |
| `GO` | `indeterminate` | 研究过程合格，但证据不足 |
| `HOLD` | 任意 | 输入、证据、执行或复核不完整，但可以恢复 |
| `FAIL / STOP` | 任意 | 存在不可恢复的泄漏、非法概率、选择性删除、证据伪造或越界行为 |

## 9. 验收方法

阶段 3 必须使用机器检查、完整注册运行、独立复算和最终人工签署的组合验收，不能只检查报告文字或顶层自报的 `PASS`。

### 9.1 输入与 Schema 验证

- 验证输入 manifest、预注册、模型注册表、特征注册表、实验记录、预测、指标、复核和 acceptance 制品。
- 核对 Phase 1、Phase 2.1、代码、配置、环境和依赖身份。
- 拒绝未知字段、未注册模型、未注册特征、错误彩种或规则段、缺失终态和身份不一致。

### 9.2 单元与 known-answer 验证

- 精确复算 M0 的组合概率。
- 验证 M1 的概率归一、合法组合、参数零值退化和固定种子复现。
- 验证时间折、特征窗口、模型评分和 Top-1000 生成的确定性不变量。
- 对核心联合概率和指标使用小规模独立参考案例进行 known-answer 对照。

### 9.3 泄漏与失败路径验证

- 注入未来期开奖、开奖后字段、全数据归一化、错误修订时间、外层目标期调参和规则段混用，系统必须拒绝。
- 注入来源期不早于目标期、预测未落盘即读取目标标签、评分后改写预测，系统必须拒绝。
- 注入非法组合、负概率、概率和不为 1、缺失实验、覆盖失败记录和越权晋级，系统必须拒绝。
- 失败、超时和崩溃必须形成可审计终态，不得覆盖为成功。

### 9.4 完整注册历史评估

- 执行全部冻结的时间折、模型和特征配置。
- 从逐期预测重新计算联合 log score、Brier、校准、负控、敏感性和稳定性。
- 检查所有注册实验均进入结果清单，不允许只提交最佳运行。
- 根据结果前冻结的规则生成模型科学分类。

### 9.5 独立 replay

- 独立复核路径只读取冻结输入和正式实验制品。
- 重建数据折分、特征快照和核心模型输入。
- 复算核心联合概率、逐期分数、汇总指标和模型分类。
- 超出冻结容差、发现泄漏或分类不一致时形成阻断问题。

### 9.6 E2E 验证

阶段 3 的 E2E 至少覆盖：

- 正常全链路研究与验收。
- 输入或规则身份不一致。
- 未来信息和开奖后字段泄漏。
- 非法组合、负概率或概率不归一。
- 时间折污染或外层目标期参与调参。
- 失败实验被删除、覆盖或遗漏。
- 历史回测越权触发 Champion 晋级。
- 独立 replay 不一致。
- 模型、特征、指标或 acceptance 制品被篡改。
- 没有 challenger 合格时仍能生成诚实的 `GO / no_shadow_candidate` 结论。

### 9.7 最终验收

- 最终 validator 从冻结输入、逐期预测、实验账本和复核制品重新计算核心指标、模型分类、交付覆盖率和阻断问题数量。
- 最终 evidence manifest 显式列出被验收制品，不使用 `latest` 指针选择结果。
- 最终验收人检查机器结果、科学表述、阶段边界和未关闭风险，签署唯一 `GO`、`HOLD` 或 `FAIL / STOP` 结论。

## 10. 决策含义

阶段 3 `GO` 只表示：

> 阶段 3 模型研究基线可信，合格 challenger 可以进入后续前瞻 shadow 验证。

阶段 3 `GO` 不表示：

- challenger 已经在真实未来开奖中优于 M0；
- 彩票已被证明存在可利用预测规律；
- 可以对外发布非均匀正式预测；
- 可以启动生产系统、自动购彩或投注；
- Top-1000 具有高中奖率或收益保证。
